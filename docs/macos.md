# macOS 双机测试

[返回文档目录](./README.md)

将同一个带版本号的 DMG 发给两台 Mac。应用标题旁显示版本号，本轮验收以控制端显示「配对完成」为准。

## 安装与配对

1. 两台 Mac 各自打开同一个版本的 DMG，将 `Koko.app` 拖入「应用程序」。
2. 在要分享的 Mac 上选「被控端」，点「启动监听」。应用默认绑定 `0.0.0.0:4444/UDP`，可以调整端口。
3. 在另一台 Mac 上选「控制端」。同局域网时输入短连接码，通过组网连接时可以粘贴「复制直连邀请」得到的内容，然后点「请求配对」。
4. 在被控端确认是刚才发起的请求，点「允许」。配对完成后连接码即失效。

应用记住上次的设备角色。每次启动监听都会生成一个新的 10 位连接码，有效期五分钟。批准的设备在本次监听期间可连接。过期后停止并重新启动监听即可生成新码。

## 通过组网连接

先让两台 Mac 加入组网，再在被控端启动监听。直连邀请会携带启动时的本机 IPv4 地址和端口，控制端尝试从中建立 QUIC 连接。短码依靠局域网自动发现，在组网没有转发发现报文时可直接使用邀请。邀请与短码共享同一次授权和有效期。

如果组网地址发生变化，重新启动监听并复制新邀请。若仍无法连接，在组网策略里核对控制端能否访问被控端的 UDP 监听端口，默认端口是 `4444`。

## 权限

设备私钥保存在各自 Mac 的 `~/.koko/` 下。被控端可随时停止监听，退出应用也会停止。

若 macOS 提示本地网络权限，在参与测试的 Mac 上允许 Koko 访问局域网。被控端的「屏幕录制」区域会显示当前权限，可点「申请录屏权限」。如果没有出现系统提示，可打开「系统设置 → 隐私与安全性 → 录屏与系统录音」，根据系统显示的应用条目授权，回到 Koko 后重新检查。[macOS 权限设计](./macos-permissions.md)

## Agent 配对

Agent 可以直接调用应用内的 CLI。同一局域网使用短码，通过组网时也可以把完整的直连邀请作为同一命令的参数：

```bash
/Applications/Koko.app/Contents/Helpers/koko-agent pair ABCDE-FGHJK
```

把示例码换成实际连接码。被控端本地批准后，命令会返回包含 `status`、`host_id` 和 `address` 的 JSON。CLI 默认复用本机 `~/.koko/controller.key`，后续 MCP 可以复用这一配对入口。

## 构建测试包

在装有 Rust 和 Xcode 命令行工具的 Mac 上，从仓库根目录运行：

```bash
./scripts/build-macos.sh
```

输出为 `target/koko-macos/Koko-<version>.dmg`，包含面向 macOS 13 及以上的 Apple Silicon 和 Intel 二进制。Rust 只用于构建，测试机器打开安装好的应用即可。

内测使用 `0.1.x`。每次发一个新的迭代包时，递增根目录 `Cargo.toml` 的 `workspace.package.version` 最后一位，使用 Cargo 更新锁文件后再打包。应用内版本、CLI 的 `--version` 和 DMG 文件名都来自同一个版本；同一版本重打包使用同一个文件名。

这是临时签名的开发测试包。若 macOS 拦截首次打开，请确认文件来自自己的构建，再按 Apple 的说明处理。面向公开发布时，使用 Developer ID 签名并公证。[Apple 应用打开说明](https://support.apple.com/zh-cn/guide/mac-help/mh40616/mac) · [Apple 分发说明](https://developer.apple.com/macos/distribution/)

## 复测

- **重启**：退出被控端后重新打开，启动监听。控制端用新连接码发起请求。
- **授权拒绝**：在被控端点「拒绝」，控制端应显示配对失败，并可用当前连接码重新请求。
- **调试**：需要查看 CLI 输出时，使用[命令行验收步骤](./implementation.md#身份与连接验收命令)。
