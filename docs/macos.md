# macOS 双机测试

[返回文档目录](./README.md)

将同一个 `Koko.dmg` 发给两台在同一局域网的 Mac。安装后的 Koko 支持验证设备身份、连接和授权。本轮验收以控制端显示「连接通过」为准。

## 安装与配对

1. 两台 Mac 各自打开 `Koko.dmg`，将 `Koko.app` 拖入「应用程序」。
2. 在发起连接的 Mac 上选「控制端」，复制控制端 ID。
3. 在另一台 Mac 上选「被控端」，粘贴控制端 ID，点「启动监听」。应用会尝试填写本机的局域网地址。有多个网络接口时，使用控制端能访问的地址。
4. 在被控端复制连接码，回到控制端粘贴，点「验证连接」。

应用会记住设备角色、控制端 ID 和上次粘贴的连接码。被控端再次打开应用后，点「启动监听」即可。局域网地址变化时，把新的连接码发给控制端。

设备私钥保存在各自 Mac 的 `~/.koko/` 下。复制按钮只会复制公钥 ID 或连接码。被控端可随时停止监听，退出应用也会停止。

## 构建测试包

在装有 Rust 和 Xcode 命令行工具的 Mac 上，从仓库根目录运行：

```bash
./scripts/build-macos.sh
```

输出为 `target/koko-macos/Koko.dmg`，包含面向 macOS 13 及以上的 Apple Silicon 和 Intel 二进制。Rust 只用于构建，测试机器打开安装好的应用即可。

这是临时签名的开发测试包。若 macOS 拦截首次打开，请确认文件来自自己的构建，再按 Apple 的说明处理。面向公开发布时，使用 Developer ID 签名并公证。[Apple 应用打开说明](https://support.apple.com/zh-cn/guide/mac-help/mh40616/mac) · [Apple 分发说明](https://developer.apple.com/macos/distribution/)

## 复测

- **重启**：退出被控端后重新打开，启动监听。控制端用保存的连接码再次验证。
- **授权拒绝**：在被控端授权另一个有效的控制端 ID，再用原控制端连接，预期提示主机未授权。
- **调试**：需要查看 CLI 输出时，使用[命令行验收步骤](./implementation.md#身份与连接验收命令)。
