# macOS 权限与远程会话

[返回文档目录](./README.md)

Koko 在被控端检查本次会话授权，在执行截图或键鼠操作时检查 macOS 权限。启动远程协助会开放一个会话。被控端可以发出一次性授权码，也可以批准从局域网列表发来的请求。两种方式的会话均支持查看和键鼠控制。

## 首次启动与重新进入

首次打开此版本时，Koko 显示「设置 Koko 的使用权限」。选择「去开启」进入「安全与隐私」，在右侧选择权限，左侧查看操作说明。录屏和辅助功能分别点击「开启」才会发起系统请求。只用作控制端，可选「暂时跳过」。首次引导期间，本机共享保持关闭。

完成或跳过后，可从主窗口「本机权限 → 管理权限」或「设置 → 安全」再次进入。从 0.1.17 起，分项权限页打开期间每秒复查一次录屏和键鼠权限；系统允许当前进程使用后，对应项目会自动打勾。若系统要求重启，或开关已打开而应用仍显示未授权，可点「重开 Koko 并复查」。应用重开后直接回到权限页，已有共享或连接时会先确认是否结束。文件夹仍由用户点击「检查」后单独验证。

Koko 在本机记录最近检查的应用版本和两项桌面权限。升级后若检测到原先可用的权限失效，主窗口会自动打开一次分项引导。上次选择「暂时跳过」并一直只作控制端的设备，可继续直接进入主窗口。

「文件与文件夹」显示当前接收位置。点击「检查」会在该目录创建并移除一个空的临时文件夹，macOS 可能询问是否允许访问。如果被拒绝，可打开对应的系统设置或在「设置 → 常规」更改接收位置，再次检查。「此目录可写」仅适用于刚刚检查的路径。发送其他受保护目录中的文件时，系统会按实际访问另行询问。[Apple 文件与文件夹访问说明](https://support.apple.com/guide/mac-help/control-access-to-files-and-folders-on-mac-mchld5a35146/mac)

## 按功能申请系统权限

| 功能 | 哪一端 | 权限与触发时机 |
| --- | --- | --- |
| 局域网通信和发现 | 两端按实际网络操作 | macOS 要求时，由建立局域网连接或搜索触发系统提示。 |
| 查看显示器 | 被控端 | 「录屏与系统录音」。被控端点击「屏幕录制」旁的「开启」才触发申请。控制端接收所选显示器的画面。 |
| 点击、按键和发送文本 | 被控端 | 「辅助功能」或系统所示的「设备控制和数据访问」。本机点击「辅助功能」旁的「开启」发起辅助功能请求，实际执行前检查发送事件权限。 |
| 剪贴板文件传输 | 发送端和接收端 | 首次读取或写入桌面、文稿或下载等受保护目录时，macOS 可能请求该目录的访问权限。可在「隐私与安全性 → 文件与文件夹」调整。 |
| 本机键鼠触发自动接管 | 被控端，后续功能 | 如果采用全局观察真实输入事件的实现，再评估「输入监控」。 |

应用进入被控端页面和回到前台时复查录屏与键鼠权限。用户可从该页面打开系统设置并手动复查。在当前阶段只使用表内已实现功能的权限。[Apple 局域网隐私技术说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Apple 隐私与安全设置](https://support.apple.com/zh-cn/guide/mac-help/mchl211c911f/mac)

## 连接与授权

1. **授权码或直连邀请**。被控端启动远程协助并发出含码邀请。控制端持有效码直接进入会话，授权码在五分钟或一次成功使用后失效。
2. **局域网连接**。发现设备时显示被控端开启共享后发布的主机名。控制端从详情页进入桌面，由被控端选择仅允许本次、信任设备或拒绝。信任绑定到 QUIC 握手确认的完整控制端公钥。同设备名或局域网地址不会继承信任。
3. **执行与撤销**。已信任设备可在本机共享开启且没有其他会话时直接连接。被控端关闭「允许远程协助」会关闭监听并结束当前会话。「清除信任」同时结束当前会话，并要求设备下次进入时重新确认。

设备信任用于 Koko 会话，macOS 锁屏与登录由系统处理。

缺少录屏权限时，控制端显示录屏提示。已有录屏权限而缺少辅助功能时，控制端仍可查看画面，键鼠请求会返回辅助功能提示。

## 包内权限归属

图形版由 `Koko.app` 检查并申请录屏与键鼠权限，收到 daemon 转发的已授权请求后，在同一进程采集显示器画面或发送键鼠操作。使用 CLI 单独启动 daemon 时，由 `koko-desktop` 处理主屏截图和基础输入。[Apple 屏幕采集示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)

请从「应用程序」打开已安装的 Koko。开启「允许远程协助」时，Koko 会列出缺少的权限。点击相应项目旁的「开启」发起系统申请，并按提示在对应权限页选中 Koko。键鼠申请使用 macOS 的辅助功能请求，系统允许发送事件后，应用才显示「已授权」。授权后回到 Koko 复查。若系统要求退出重开，按系统提示操作。[Apple 辅助功能申请接口](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)

新版本 macOS 可能要求先发起申请，再从系统列表选择应用。先使用 Koko 的权限申请按钮。设置页面名称及选择方式取决于 macOS 版本。若页面提供「＋」而列表里没有 Koko，可用「＋」添加「应用程序」里的 Koko。若启用辅助功能后键鼠仍显示「未授权」，回到 Koko 再点一次「辅助功能」旁的「开启」。[Apple 关于 macOS 27.3 权限调整的说明](https://developer.apple.com/news/?id=oqng0zjk)

### 为什么升级后会再次询问

macOS 会核对新应用是否满足旧授权记录里的代码签名要求。临时签名通常依赖具体构建的哈希，重新编译就可能改变它。此时「应用程序」里的名称、安装路径和系统权限开关都可能和以前一样，但新进程仍无法录屏或发送键鼠事件。[Apple 代码签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

RustDesk 的 macOS 客户端通过系统接口检查或申请权限，公开发布流程为 macOS 应用签名并提交公证。正常升级时，macOS 可以复用符合签名要求的已有授权。RustDesk 的安装文档也保留了旧录屏授权失效时移除旧条目的排查步骤。[RustDesk 权限实现](https://github.com/rustdesk/rustdesk/blob/master/src/platform/macos.rs) · [RustDesk 构建流程](https://github.com/rustdesk/rustdesk/blob/master/.github/workflows/flutter-build.yml) · [RustDesk macOS 安装说明](https://rustdesk.com/docs/en/client/mac/)

KoKo 覆盖安装后，先从「应用程序」打开，运行「测试本机画面」，再用被控端的「键鼠测试区」验证输入。两项均通过即可继续共享。只有某项失败、对应开关却已开启时，再退出 KoKo，在该权限页移除旧条目并添加当前安装的 KoKo。

已重装且系统仍核对旧签名时，可以在被控端退出 Koko 后，用下面的命令清除 Koko 的三条授权记录，再打开应用重新授权。命令按 Koko 的应用标识限定范围。

```bash
tccutil reset ScreenCapture io.github.kizai.koko
tccutil reset Accessibility io.github.kizai.koko
tccutil reset PostEvent io.github.kizai.koko
```

后续版本保持应用标识 `io.github.kizai.koko`、签名团队和签名类型一致。内测可沿用钥匙串中的 Apple Development 身份，公开分发使用 Developer ID 并完成公证。发布前可把 `KOKO_PREVIOUS_APP` 指向上一版，检查新旧签名的指定要求是否相互兼容。macOS 根据签名要求识别升级后的应用，系统仍会按用户选择、设备策略和系统版本判定实际权限。第一次由临时签名换成证书签名时，为新身份授权一次。[构建与升级校验](./macos.md#公开分发与升级) · [Apple 代码签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

## 双机验收

| 场景 | 预期 |
| --- | --- |
| 控制端搜索局域网 | 显示设备列表，被控端保持等待状态。 |
| 在局域网设备详情页点击「进入桌面」 | 被控端显示确认。拒绝时不开放截图或输入。 |
| 使用有效授权码 | 直接进入远程会话，无需再次确认。 |
| 缺少录屏或辅助功能权限 | 分别收到画面和输入权限提示。 |
| 首次启动或升级后首次进入引导 | 显示权限概览。点击「去开启」可查看三项权限，点击「返回」可回到概览。选「暂时跳过」后可直接控制其他设备，重启后进入主窗口。 |
| 在首次引导申请权限后按系统提示重启 | 继续显示「安全与隐私」，已生效权限显示勾选。点击「完成」后，共享仍关闭。 |
| 升级后原有录屏或键鼠权限失效 | 已完成引导的用户看到一次复查提示。同版本再次打开不重复；只作控制端并已跳过的用户保持原选择。 |
| 在首次引导、主窗口或设置的权限页点「重开 Koko 并复查」 | 权限弹窗先关闭，旧进程退出。仅一个新进程启动并显示「安全与隐私」。若已开启共享，取消确认应保留原会话。 |
| 从「设置 → 安全」重新进入 | 可查看实际授权状态，打开系统设置，回到前台或手动复查。 |
| 更改接收位置并检查文件权限 | 展示新路径及其实际检查结果。可写目录通过，被拒绝或不存在的目录给出不同提示。 |
| 首次开启本机共享 | 显示缺项及对应申请入口。取消时不启动监听。 |
| 升级测试包后重新授予录屏权限 | 完全退出并重开 Koko 后，被控端显示「已授权」，重新连接时控制端收到画面。 |
| 两项权限均已授予 | 「测试本机画面」能取到截图。打开被控端「键鼠测试区」，用控制端点击「测试点击」，选中文本框并发送 Koko。测试区应分别显示「已收到点击」和「已收到文本」。 |
| 同一 Apple 签名身份升级 | 安装证书签名的旧版本并授权，覆盖安装同一签名团队、类型和应用标识的新版本，复查录屏、点击和文本输入。 |
| 未配对设备或已结束会话的设备尝试操作 | 主机拒绝请求。 |
