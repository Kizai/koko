# macOS 权限设计

[返回文档目录](./README.md)

下一阶段的目标是让控制端按需查看被控端主显示器的一张截图。一次截图需要同时满足三个条件：两端能通过局域网通信，主机已授权该控制端且本次监听已开启屏幕共享，macOS 已允许实际采集进程录屏。前两项中的设备和会话授权由 Koko 主机执行，系统权限由本机用户在 macOS 中决定。

## 按功能申请权限

| 功能 | 哪一端 | 系统权限与触发时机 |
| --- | --- | --- |
| 局域网验证（已实现） | 两端按实际网络操作 | macOS 要求授权时，由首次受保护的局域网操作触发。应用包已带 `NSLocalNetworkUsageDescription`。连接超时时保留网络排查入口，并提示用户检查「隐私与安全性 → 本地网络」。 |
| 录屏许可（已实现入口） | 被控端 | 被控端页面检查「录屏与系统录音」权限，用户点「申请录屏权限」时才触发系统请求。支持返回应用自动复查和手动复查。 |
| 按需截图（下一阶段） | 被控端 | 用户启用本次会话的屏幕共享后，主机在实际采集时检查许可。控制端接收并显示 PNG。 |
| 键鼠控制（后续） | 被控端 | 用户启用远程输入时，根据实际用于发送事件的 API 检查「辅助功能」或对应的事件发送授权。主机同时执行设备能力和控制租约。 |
| 本机键鼠触发自动接管（后续） | 被控端 | 只有采用全局观察真实输入事件的实现时才评估「输入监控」。在用户主动启用自动接管时请求与所用 API 对应的权限。 |

截图阶段的权限清单只有局域网和被控端录屏。麦克风、摄像头、自动化和完全磁盘访问留给实际使用这些能力的功能单独评估。[Apple 局域网隐私技术说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Apple 隐私与安全设置](https://support.apple.com/zh-cn/guide/mac-help/mchl211c911f/mac) · [Core Graphics 权限接口](https://developer.apple.com/documentation/coregraphics/core-graphics-functions) · [辅助功能信任检查](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)

## 屏幕共享采用会话授权

| 方式 | 取舍 |
| --- | --- |
| 每张截图都由被控端确认 | 能逐次决定是否分享，适合偶发或临时需求。反复点击会打断双机验收和后续的只读 MCP。 |
| 每次监听会话主动开启 | 一次本机操作即可在本次会话中按需截图。关闭共享或结束监听后，下次使用需重新开启。 |
| 针对已配对设备长期记住共享授权 | 启动后操作最少，需要能明确审计、撤销及提示常驻的共享授权。 |

下一阶段采用**每次监听会话主动开启**。被控端打开 Koko、切换角色和启动监听时仍可验证连接。本机用户点「启用屏幕共享」时，界面说明当前授权的控制端和共享目标是主显示器。设备配对信息继续保存，正在共享的状态随监听会话结束。

1. **在被控端触发授权。** 用户点「启用屏幕共享」后，录屏未授权时显示「等待录屏授权」，通过实际负责采集的代码路径执行系统请求。用户拒绝或返回应用后仍未授权时，显示「系统设置 → 隐私与安全性 → 录屏与系统录音」路径，并让用户再次检查。系统要求重新打开应用时，按提示重启。
2. **在主机执行截图授权。** 只信任由 QUIC 握手确认的控制端公钥。对已授权连接，先检查本机用户是否在本次会话中主动启用共享，再由实际采集路径检查 OS 权限并尝试截图。分别返回「屏幕共享未开启」「被控端需要录屏权限」或采集失败。远端请求本身不会发起系统授权。
3. **在控制端显示结果。** 提供「获取截图」动作，成功时显示一张 PNG。缺少权限时给出被控端操作提示。连接失败、主机拒绝和需要录屏权限使用不同提示。
4. **在被控端停止共享。** 被控端显示共享状态并提供「停止共享」。关闭、停止监听或重开应用后，新请求需要重新启用共享。操作系统撤销录屏权限后，下一次截图应失败并返回可区分的结果。

## 先验证打包后的权限归属

当前 `Koko.app` 是 SwiftUI 启动器，由包内的 Rust `koko-daemon` 执行被控端任务。开发时先将测试 DMG 中的应用安装到「应用程序」，验证 macOS 把录屏许可记在哪个应用条目下。采集进程使用 `CGPreflightScreenCaptureAccess` 检查权限，申请入口只由被控端本机用户触发。若界面进程与 helper 的检查结果不同，以实际采集进程的结果为准，并确保请求与采集归属同一受系统识别的应用身份。用目标系统上的实测结果决定是否调整进程边界。[Apple 屏幕采集示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) · [Apple 屏幕录制设置](https://support.apple.com/zh-cn/guide/mac-help/mchld6aa7d23/mac)

测试包目前使用临时签名。macOS 用代码签名要求识别应用，换包后可能重新询问权限。保留稳定的 bundle ID，并在能使用 Apple 签名身份时用同一身份签发连续测试包。正式分发使用 Developer ID 签名并公证。签名用于识别应用，用户仍在 macOS 中决定授权。[Apple 代码签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) · [Apple macOS 分发](https://developer.apple.com/macos/distribution/)

## 双机验收

| 场景 | 预期 |
| --- | --- |
| 只启动监听 | 控制端可验证连接。请求截图时显示共享未开启。 |
| 被控端拒绝录屏 | 控制端收到录屏权限提示，连接验证仍可通过。 |
| 被控端授予录屏且开启共享 | 控制端看到被控端主屏上的测试文字。 |
| 被控端停止共享、撤销录屏或重启 | 下一次截图失败，提示能区分缺少共享授权与缺少系统权限。 |
| 未配对设备请求截图 | 主机拒绝该设备，采集入口不执行。 |
| 用新版 DMG 替换应用 | 记录需要重新授权的 macOS 版本、应用条目和签名方式。 |
