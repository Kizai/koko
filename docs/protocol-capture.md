# macOS 协议样例采集

[返回文档目录](./README.md)

在一台已登录图形桌面的 Mac 上，从仓库根目录运行以下命令。需要能执行本地 macOS 构建的 Xcode 工具链和 Python 3。脚本在 Git 忽略的构建目录中新建 `target/protocol-capture-*/`（权限 `0700`），也可以用 `--output 新目录名` 指定一个尚不存在的目录。成功后目录中有一个 `capture.tar.gz`（权限 `0600`）。归档只保存在本机，由操作者决定是否分享。失败可能留下空的输出目录。

```sh
./scripts/capture-protocol.sh
```

1. 准备可公开的测试窗口、壁纸和桌面。屏幕图像和系统音频会原样进入归档。关闭其他播放源以及包含私人信息的窗口、通知。
2. 脚本构建本地 ad hoc 版，在 `target/koko-macos/local/.capture-*/Koko.app` 内替换测试副本的 helper 并重新签名。修改和清理都在本地构建目录进行。构建完成后，原 `local/Koko.app` 中的 daemon 在正常退出和 Ctrl+C 中断时都保留原文件。脚本在构建前检查路径，发现会让应用写入重定向的符号链接就停止。若 **Koko Protocol Capture** 请求访问日常 Koko 自定义验证码的钥匙串项目，请点**拒绝**。随后按测试 App 中的提示授予屏幕录制与辅助功能权限，开启被控端共享。macOS 可能要求重开测试 App。
3. 收到名为 **Protocol Capture** 的人类配对请求时，点击仅允许本次。将 Koko 窗口隐藏，点击准备好的测试窗口使其处于前台。脚本等待 15 秒后自动采集，并在两次录制期间播放系统测试提示音。
4. 成功后终端显示归档位置。失败时检查测试 App 的权限、配对决定和声音输出，再重新运行。提交样例前先在本机确认图像、UI 树和音频的内容均可分享。

## 实际记录

- `requests.jsonl`、`replies.jsonl` 保留 daemon 的 `Desktop request: N JSON` 与 App 的 `desktop-reply N JSON` 原行，包括空格和换行。脚本用编号对齐请求与回复。`desktop.cli.jsonl` 另存 CLI 实际返回的 JSON；CLI 会重新编码回复，并给部分回复增加连接信息。
- 桌面请求覆盖主屏枚举、前台 UI 树、屏幕截图、壁纸及指定显示器的 JPEG / PNG 采集。两轮 H.264 录制分别关闭、开启反馈。`video-feedback-{off,on}.bin` 是 CLI 输出的完整合并流。`audio:true` 使 `remote-video` 另开真实 `audio` 请求，脚本把类型 5、6 的原始带长度记录复制到对应 `audio-feedback-*.bin`。当前 CLI 没有独立录音命令。
- `metadata.json` 记录提交、构建前有无未提交文件（`source_dirty`）、macOS 与 App 版本、采集副本的 bundle ID、UTC 时间、显示器、请求参数、录制时长、记录数和音频格式。开启反馈时，从类型 10 读取实际硬件或软件编码器与采集 API。按原始记录到达时间统计每次测试声音播放窗口的音频包数，并记录视频首末帧到达时间；静态画面的低帧数不会单独导致失败。无反馈流没有这一报告。当前版本不再发送类型 7，Windows 端不实现发送。
- `SHA256SUMS` 列出每个采集数据文件的相对路径和 SHA-256。清单自身不参与散列。解包到空目录，在该目录运行 `shasum -a 256 -c SHA256SUMS` 复核。

## 本机隔离与边界

脚本直接启动名为 Koko Protocol Capture 的一次性副本，其独立标识符 `io.github.kizai.koko.capture` 对应专用的偏好设置域。自定义验证码的钥匙串服务名固定为 `io.github.kizai.koko.custom-code`，拒绝访问该项后仍可通过 GUI 批准本次配对。若副本尝试向 daemon 提交非空自定义码，脚本会中止本轮采集，避免触发 App 在验证码被拒绝后清空钥匙串项的逻辑。它让被控端监听 `127.0.0.1` 的动态端口，并使用临时主机身份和独立的临时控制端身份。它根据公开的设备 ID、主机公钥及实际监听端口发起正常 GUI 批准流程。验证模式和授权决定由 App 保持。用于 GUI 正常显示的验证码与邀请只在原有管道中转发。候选 Desktop 行及其已知图片字段解码后的字节经过泄漏检测后才进入 `tee`，归档前再扫描候选文件。候选数据中检测到私钥、验证码或邀请即中止整轮采集，归档不会发布。脚本未记录一般 stdout、stderr 或私钥。字节扫描无法识别画面中可见或音频中念出的秘密。

原 daemon 保存在同一 Helpers 目录，以维持其对 `koko-desktop` 的同级路径查找。App 使用私有 HOME 和 Foundation 主目录；每次启动 daemon 单独记录监听、批准和最终扫描状态；开始配对后若实例更换，本次采集停止。脚本在确认副本及其辅助进程退出后发布归档并清理临时目录。若无法确认进程退出，则报告私有目录以便核查。系统授予这份 App 的 TCC 权限仍由 macOS 管理。

收到真实材料后再补 `koko-proto` 的 displays、ui_tree、音视频样例测试，用于阶段 0B 的字节级比对。脚本的管道、归档、路径隔离和截断负例使用合成输入，只验证采集工具。当前尚待用户执行首次实机 GUI 采集。
