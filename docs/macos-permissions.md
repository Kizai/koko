# macOS 权限与远程会话

[返回文档目录](./README.md)

Koko 在被控端检查本次会话授权，在执行截图或键鼠操作时检查 macOS 权限。启动远程协助会开放一个会话。被控端可以发出一次性授权码，也可以批准从局域网列表发来的请求。两种方式的会话均支持查看和键鼠控制。

## 按功能申请系统权限

| 功能 | 哪一端 | 权限与触发时机 |
| --- | --- | --- |
| 局域网通信和发现 | 两端按实际网络操作 | macOS 要求时，由建立局域网连接或搜索触发系统提示。 |
| 查看显示器 | 被控端 | 「录屏与系统录音」。被控端点击「申请录屏权限」才触发申请。控制端接收所选显示器的画面。 |
| 点击、按键和发送文本 | 被控端 | 「辅助功能」或系统所示的「设备控制和数据访问」。本机点击「申请键鼠权限」发起辅助功能请求，实际执行前检查发送事件权限。 |
| 剪贴板文件传输 | 发送端和接收端 | 首次读取或写入桌面、文稿或下载等受保护目录时，macOS 可能请求该目录的访问权限。可在「隐私与安全性 → 文件与文件夹」调整。 |
| 本机键鼠触发自动接管 | 被控端，后续功能 | 如果采用全局观察真实输入事件的实现，再评估「输入监控」。 |

应用进入被控端页面和回到前台时复查录屏与键鼠权限。用户可从该页面打开系统设置并手动复查。在当前阶段只使用表内已实现功能的权限。[Apple 局域网隐私技术说明](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) · [Apple 隐私与安全设置](https://support.apple.com/zh-cn/guide/mac-help/mchl211c911f/mac)

## 连接与授权

1. **授权码或直连邀请**。被控端启动远程协助并发出含码邀请。控制端持有效码直接进入会话，授权码在五分钟或一次成功使用后失效。
2. **局域网连接**。发现设备时显示被控端开启共享后发布的主机名。控制端从详情页进入桌面，由被控端选择仅允许本次、信任设备或拒绝。信任绑定到 QUIC 握手确认的完整控制端公钥。同设备名或局域网地址不会继承信任。
3. **执行与撤销**。已信任设备可在本机共享开启且没有其他会话时直接连接。被控端关闭「允许远程协助」会关闭监听并结束当前会话。「清除信任」同时结束当前会话，并要求设备下次进入时重新确认。

设备信任用于 Koko 会话，macOS 锁屏与登录由系统处理。

缺少录屏权限时，控制端显示录屏提示。已有录屏权限而缺少辅助功能时，控制端仍可查看画面，键鼠请求会返回辅助功能提示。

## 包内权限归属

图形版由 `Koko.app` 检查并申请录屏与键鼠权限，收到 daemon 转发的已授权请求后，在同一进程采集显示器画面或发送键鼠操作。使用 CLI 单独启动 daemon 时，由 `koko-desktop` 处理主屏截图和基础输入。[Apple 屏幕采集示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)

请从「应用程序」打开已安装的 Koko。开启「允许远程协助」时，Koko 会列出缺少的权限。点击「申请录屏权限」或「申请键鼠权限」发起系统申请，并按提示在对应权限页选中 Koko。键鼠申请使用 macOS 的辅助功能请求，系统允许发送事件后，应用才显示「已授权」。授权后回到 Koko 复查。若系统要求退出重开，按系统提示操作。[Apple 辅助功能申请接口](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)

新版本 macOS 可能要求先发起申请，再从系统列表选择应用。先使用 Koko 的权限申请按钮。设置页面名称及选择方式取决于 macOS 版本。若页面提供「＋」而列表里没有 Koko，可用「＋」添加「应用程序」里的 Koko。若启用辅助功能后键鼠仍显示「未授权」，回到 Koko 再点一次「申请键鼠权限」。[Apple 关于 macOS 27.3 权限调整的说明](https://developer.apple.com/news/?id=oqng0zjk)

临时签名的测试包每次重新构建都可能换签名。卸载或覆盖应用后，旧授权记录可能仍在。录屏和键鼠事件分别受系统核验，开关显示开启时，当前构建也可能被拒绝。先退出 Koko，在对应设置页移除旧条目，再添加「应用程序」里的 Koko。[Apple 代码签名要求](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

已重装且系统仍核对旧签名时，可以在被控端退出 Koko 后，用下面的命令清除 Koko 的三条授权记录，再打开应用重新授权。命令按 Koko 的应用标识限定范围。

```bash
tccutil reset ScreenCapture io.github.kizai.koko
tccutil reset Accessibility io.github.kizai.koko
tccutil reset PostEvent io.github.kizai.koko
```

后续升级沿用 Apple 签名团队、签名类型和应用标识。可以用[签名校验构建](./macos.md#构建测试包)生成供两台 Mac 复测的包。第一次由临时签名换成证书签名时，为新身份授权一次。公开分发使用 Developer ID 签名并公证。[Apple macOS 分发](https://developer.apple.com/macos/distribution/)

## 双机验收

| 场景 | 预期 |
| --- | --- |
| 控制端搜索局域网 | 显示设备列表，被控端保持等待状态。 |
| 在搜索结果点击「远程控制」 | 被控端显示确认。拒绝时不开放截图或输入。 |
| 使用有效授权码 | 直接进入远程会话，无需再次确认。 |
| 缺少录屏或辅助功能权限 | 分别收到画面和输入权限提示。 |
| 首次开启本机共享 | 显示缺项及对应申请入口。取消时不启动监听。 |
| 升级测试包后重新授予录屏权限 | 完全退出并重开 Koko 后，被控端显示「已授权」，重新连接时控制端收到画面。 |
| 两项权限均已授予 | 「测试本机画面」能取到截图。打开被控端「键鼠测试区」，用控制端点击「测试点击」，选中文本框并发送 Koko。测试区应分别显示「已收到点击」和「已收到文本」。 |
| 同一 Apple 签名身份升级 | 安装证书签名的旧版本并授权，覆盖安装同一签名团队、类型和应用标识的新版本，复查录屏、点击和文本输入。 |
| 未配对设备或已结束会话的设备尝试操作 | 主机拒绝请求。 |
