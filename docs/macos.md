# macOS 双机测试

[返回文档目录](./README.md)

将同一个带版本号的 DMG 发给两台 Mac。应用标题旁显示版本号，本轮验收以控制端能看到被控端主屏并操作一个测试窗口为准。

## 安装与配对

1. 两台 Mac 各自打开同一个版本的 DMG，将 `Koko.app` 拖入「应用程序」。
2. 在要分享的 Mac 上查看录屏和辅助功能权限，再打开「本机共享」里的「允许远程协助」。应用默认绑定 `0.0.0.0:4444/UDP`，可以调整端口。
3. **授权码连接**。另一台 Mac 在「连接伙伴」输入短码或粘贴组网直连邀请。点击「连接」后打开远控窗口。
4. **局域网搜索连接**。用侧栏的刷新按钮搜索，并点选目标设备。被控端此时会显示请求，用户点「允许」后进入会话。

每次打开本机共享都会生成一个新的 10 位码，有效期五分钟，允许切换显示器、查看和控制键鼠，用过一次即失效。控制端从「控制中心」结束本次会话。被控端关闭「允许远程协助」即可撤销授权并关闭监听。

## 通过组网连接

先让两台 Mac 加入组网，再在被控端启动远程协助。直连邀请会携带启动时的本机 IPv4 地址和端口，控制端尝试从中建立 QUIC 连接。短码依靠局域网自动发现，在组网没有转发发现报文时可直接使用邀请。邀请与短码共享同一次授权和有效期。

如果组网地址发生变化，重新启动远程协助并复制新邀请。若仍无法连接，在组网策略里核对控制端能否访问被控端的 UDP 监听端口，默认端口是 `4444`。

## 权限

设备私钥保存在各自 Mac 的 `~/.koko/` 下。被控端可随时停止监听，退出应用也会停止。

若 macOS 提示本地网络权限，在参与测试的 Mac 上允许 Koko 访问局域网。开启本机共享时，Koko 会显示缺少的录屏和辅助功能权限。用引导中的按钮发起系统申请。连接前可以点「测试本机画面」，确认当前 Koko 能采集主屏。若系统开关已开但应用仍显示「未授权」，按权限文档处理旧授权记录。[macOS 权限设计](./macos-permissions.md#包内权限归属)

## 画面与按键映射

连接后，远控窗口顶栏显示被控端名称和可用显示器。点击显示器标签切换画面，窗口按所选显示器的比例缩放。右上角「控制中心」可以选择画质、传输分辨率和全屏。自适应分辨率根据窗口可用像素与传输耗时调整，自动画质会根据取帧耗时调整 JPEG 压缩。传输分辨率只改变远控画面大小。测试版按需采集 JPEG 帧，最高支持 4096 像素长边。

在图像范围内移动鼠标、点击、拖拽或滚动会操作选中的远端显示器。支持左键、右键、中键、双击、水平及垂直滚动。留白区域保持本地操作，跨出图像范围时已开始的拖拽会到画面边缘。被控端需要授予辅助功能权限。「控制中心」也提供快捷键和文本输入。

| 控制端操作 | 被控端动作 |
| --- | --- |
| 回车、Esc、Tab、删除、空格、方向键 | 按对应的 macOS 键，删除为 Backspace |
| ⌘A、⌘C、⌘V、⌘Z | 在被控端执行全选、复制、粘贴和撤销 |
| 输入文本并点「发送文本」 | 向当前聚焦的远端应用发送文本 |

⌘C 与 ⌘V 操作被控端自己的剪贴板。

## Agent 配对

Agent 可以直接调用应用内的 CLI。同一局域网使用短码，通过组网时也可以把完整的直连邀请作为同一命令的参数：

```bash
/Applications/Koko.app/Contents/Helpers/koko-agent pair ABCDE-FGHJK
```

把示例码换成实际连接码。命令返回包含 `status`、`host_id` 和 `address` 的 JSON。CLI 默认复用本机 `~/.koko/controller.key`。 `koko-agent discover` 只列出设备，使用设备的 `request` 字段发起配对才会请求被控端确认。后续 MCP 可以复用这些入口。

## 构建测试包

在装有 Rust 和 Xcode 命令行工具的 Mac 上，从仓库根目录运行：

```bash
./scripts/build-macos.sh
```

输出为 `target/koko-macos/Koko-<version>.dmg`，包含面向 macOS 13 及以上的 Apple Silicon 和 Intel 二进制。Rust 只用于构建，测试机器打开安装好的应用即可。

内测使用 `0.1.x`。每次发一个新的迭代包时，递增根目录 `Cargo.toml` 的 `workspace.package.version` 最后一位，使用 Cargo 更新锁文件后再打包。应用内版本、CLI 的 `--version` 和 DMG 文件名都来自同一个版本。同一版本重打包使用同一个文件名。脚本校验新 DMG 后清理输出目录里的旧版 Koko DMG。

默认使用临时签名。若钥匙串中已有代码签名证书和私钥，可设置 `KOKO_SIGN_IDENTITY`，传入 `security find-identity -v -p codesigning` 列出的身份名称或 SHA-1。后续测试包使用同一个签名身份和应用标识，以便 macOS 识别为同一个应用。

```bash
KOKO_SIGN_IDENTITY="Developer ID Application: YOUR NAME (TEAMID)" ./scripts/build-macos.sh --require-apple-signing
```

用于验证权限能否随升级保留时，使用 `--require-apple-signing`。脚本要求显式选择钥匙串中的签名身份，并在生成 DMG 前验证 Apple 证书签名。

若 macOS 拦截首次打开，请确认文件来自自己的构建，再按 Apple 的说明处理。面向公开发布时，使用 Developer ID 签名并公证。[Apple 应用打开说明](https://support.apple.com/zh-cn/guide/mac-help/mh40616/mac) · [Apple 分发说明](https://developer.apple.com/macos/distribution/)

## 复测

- **重启**：退出被控端后重新打开，启动远程协助。控制端用新连接码发起请求。
- **授权拒绝**：从局域网列表点击「远程控制」后在被控端点「拒绝」，控制端应显示配对失败。
- **画面与输入**：切换远端显示器并缩放控制窗口，验证鼠标四角映射、双击、拖拽、右键和滚动。切换传输分辨率，查看「控制中心」里的当前画面大小。分别撤销录屏与辅助功能权限，核对各自的错误提示。
- **调试**：需要查看 CLI 输出时，使用[命令行验收步骤](./implementation.md#身份与连接验收命令)。
